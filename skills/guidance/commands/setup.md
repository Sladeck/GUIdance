# `/guidance setup`

**A. Understand the project.** Read, do not guess:
1. Find the project root and work out where styling lives, whatever the stack: a global stylesheet, a Tailwind entry CSS, a theme object (`createTheme`, a Chakra or Mantine theme), Sass variables, a component library's variables (shadcn's `--primary`, Bootstrap's `$primary`), or native theme code (SwiftUI asset catalog or `Color` extension, Compose `ColorScheme`, Flutter `ThemeData`, React Native theme). Tokens go where the project already defines styling, in its own format and naming. `references/data/stacks.md` lists traps for common stacks (MUI, Tailwind, shadcn, Bootstrap); read only your stack's section before writing.
2. List the existing tokens: CSS custom properties, Sass variables, theme objects and token files (`tokens.ts`, `theme.ts`, `*.tokens.json`). Follow aliases (`$space-sm: var(--x-space-sm)`) to the real value and the file that defines it. Compare spacing, radius, type and durations with `references/data/scales.md`, and note each off-scale value with its nearest scale value.
3. Learn what the product is from the README, PRODUCT.md or DESIGN.md, the package description, page titles and metadata. Collect brand colours: tokens named brand, primary, accent or main, and colours in logo or favicon SVGs.
4. Tell the user in a few lines what you found, including, when the project has no density role tokens yet, two spacing directions built as in `commands/spacing.md` step 2 (tables only, no screenshots at this point); the user picks A, B or the untuned preset. If the product is unclear, ask first and propose the directions after the answers. A project that already has role tokens keeps them: state its current density and point to `/guidance spacing` to change it. If the product, its users or the brand are unclear, ask in one question set: what it is, who uses it, the feel (calm, bold, playful, serious, premium), light or dark first, any brand colour. Skip what the project already answered.

**B. Colour wizard** (skip if the user keeps their colours)
5. Pick two directions, one line each on why. Use neutral surfaces by default (`surfaces: "neutral"`, see `references/data/colour.md`): near-grey backgrounds with colour on actions is how large products look; offer tinted surfaces only for expressive, brand-heavy products. `two_tone` (deep brand plus one bright accent, as in many admin dashboards) is a third option for products that want one strong highlight colour. With a brand colour: `tonal_spot` (calm) and `fidelity` (exact brand kept) or `vibrant`. Without one: two hues that fit the product, as `tonal_spot` and `neutral` (or `expressive` for playful products). Mood is judgment: say so.
6. Find the row for each brand colour with `references/data/colour.md` (HSL hue rounded to 5, or `grey`). For fidelity, also decide the brand's role there (primary or primary-container). The palette tables are large (one line per hue, about 140KB per file): never read a whole table. Search it for the line that starts with the row name and a space (for example `h140 ` or `grey `) and use only that line.
7. Preview: copy `assets/preview.html` to a scratch location (never into the project unless asked) and edit only its CONFIG block: title, then one entry per palette with `name`, `row`, `variant` and, for fidelity, `brand`, plus `surfaces: "neutral"` unless the product calls for tinted backgrounds. The page computes the same colours as the tables, checks 120 role pairs, shows the result and flags any failure. Show it: publish it as an artifact where artifacts exist; otherwise open the file in the user's browser or give them the path. Say it shows sample components, not their app.
8. Ask which one (A, B, adjust, or none). Adjusting means another row or variant and a new preview, never hand-edited hex values.

**C. Write the tokens**
9. **Project already has tokens**: do not add a parallel set. List off-scale values with their nearest scale value and ask which to move (one question, multi-select): moving radius or durations changes how the app looks. Edit values where they are defined (the token source file, not aliases). Add only missing categories, following the project's naming; the density role tokens count as one (Density section of `references/data/scales.md`, pointing at the project's own spacing tokens), for the spacing direction picked in step 4 (the plain preset that fits the product if the user did not pick), applied as in `commands/spacing.md` step 4 with its touch floor, phone-width and compact bullets. For the chosen palette, map its roles onto existing colour names where they match and add the rest.
10. **No token system yet**: create one token file in the stack's own format, next to where styling lives, with every category: spacing, the density role tokens for the spacing direction picked in step 4 (the plain preset that fits the product if the user did not pick) (Density section of `references/data/scales.md`; the worked examples do not include them, so add them after the spacing scale with a `density:` comment, applied as in `commands/spacing.md` step 4 with its touch floor, phone-width and compact bullets), radius, elevation, type, motion, targets, focus and the chosen palette's colour roles for light and dark (values from `references/data/scales.md` and the palette row, copied exactly, with the fidelity substitution and the neutral surface roles if chosen). `references/formats/` has complete worked examples for plain CSS, Tailwind v4 and v3, MUI and Sass: use the closest one as the model (names, sections, dark-mode wiring) and translate it for other stacks. Show the file and the wiring line before writing; never overwrite an existing file. Then add the wiring line to their entry file.
11. Put a short comment in the token file recording the palette: variant, row and brand colour, so it can be regenerated.
12. Check: every colour you wrote must match the table row character for character. If a browser is available, open the app and run the contrast check (`checks/contrast.js`, see `references/browser-checks.md`).
13. Finish with what changed (files and values) and what to verify visually. Do not commit.
