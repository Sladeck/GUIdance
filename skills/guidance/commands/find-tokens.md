# Find the tokens

Used by `/guidance setup`, `/guidance spacing` and `/guidance shape` (step 1 of each).

1. Find the project root and work out where styling lives, whatever the stack: a global stylesheet, a Tailwind entry CSS, a theme object (`createTheme`, antd's `ConfigProvider` `theme`, a Chakra or Mantine theme), Sass variables, a component library's variables (shadcn's `--primary`, Bootstrap's `$primary`), or native theme code (SwiftUI asset catalog or `Color` extension, Compose `ColorScheme`, Flutter `ThemeData`, React Native theme). Note the component library the project depends on, if any (`package.json`, the Gradle or Swift package files). Tokens go where the project already defines styling, in its own format and naming. `references/data/stacks.md` lists traps for common stacks (MUI, Ant Design, Tailwind, shadcn, Bootstrap, Jetpack Compose, SwiftUI); read only your stack's section before writing.
2. Read `design-decisions.md` at the root if GUIdance wrote it (`references/formats/decisions.md`): its lines are earlier decisions (tuned roles, pages, accepted risks) that this run keeps unless the user changes them. List the existing tokens: CSS custom properties, Sass variables, theme objects and token files (`tokens.ts`, `theme.ts`, `*.tokens.json`). A `:root` block of custom properties in a stylesheet is a token source, even with only a few variables and no file named tokens; so is a Sass partial of variables. Follow aliases (`$space-sm: var(--x-space-sm)`) to the real value and the file that defines it, and name each one in the summary ("`--brand` is an alias of `--main-color`: one colour").
3. Convert units first (`.35s` is 350ms, `1rem` is 16px). Look at every value in use, not only the tokens: raw values in stylesheets, component files and inline styles count.
